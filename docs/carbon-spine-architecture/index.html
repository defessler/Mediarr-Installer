The mental model

Six stacked layers, and a feedback path

Each layer is derived from the one above it. Only Layer 1 is authoritative. Everything below can be deleted and rebuilt — and everything the runtime discovers comes back up through intent, never as a parallel write.

0

Source / creation

Authoring tools, validated durable templates, creation recipes. Clone and materialization produce detached durable proposals: fresh BUIDs, BaseId provenance, references remapped. This is upstream of the Coordinator, which owns generic structural legality and nothing about what a Zombie is made of.

1

Durable facts

ECS entities carrying durable Carbon components: BUID identity, parentage, payload, durable references, provenance, Representation Markers. This is the only authority. Generation stamps live here too, but as rebuildable acceleration metadata rather than authoritative meaning.

2

Spine

The logical hierarchy and its rebuildable indexes: ancestry, children, subtree, scope, pruning. The hierarchy is durable because parentage is durable. The indexes that make it fast are not.

3

Control / derivation

Coordinator → Publication → Watcher, and alongside them Driver demand → Residency Solver → Context Scope host → concern Filter → Orchestrator. Mutation, settlement, localization, eligibility, runtime-scope lifetime, and complete Desired derivation. None of it holds authority of its own.

4

Contextual working state

Scope-owned systems, caches, target sets, binding buckets, retirement barriers, transient link and service caches. All of it disposable. Owned by the Context Scope where those lifetime semantics align — and by an explicit concern-local partition key where they do not.

5

Projection

Reconcilers, Warehouse leases, delivery packages, manifests, presenters, GameObjects, Scenes, physics, audio, rendering. Expensive, asynchronous, stateful, useful — and never durable.

Durable truth says what exists and where. Everything else discovers, interprets, caches, simulates, or represents that truth.
Runtime consequences are derived from durable change rather than being manually orchestrated by the endpoint that requested the change.
And the loop closes upward through intent. Payload outcomes return by targeted sanctioned writeback; structural facts the engine observes become domain intent for the Coordinator. Neither becomes a second write path.

About this page

Built from CARBON-SPINE-TO-PROJECTION-FUNCTIONAL-ARCHITECTURE-FLOW-AUDITED-V2.md, audited 2026-08-12 against the August 10 canonical master and August 11 owner clarification, with a second end-to-end flow-completeness audit. Section markers throughout the panels point back to that document. Where it specifies concrete C# structs, native container choices, target-partition buffers, binding handles, the constrained first-slice pairing, or exact system types, those are recommended minimum functional implementation choices, not canonical decisions — the open ones are listed in §36 of the source.

The audit corrected several things this page previously showed the old way: DeliveryKey is now Barcode; BaseId is immediate-source provenance rather than an asset slot ID; Actual is not Ready, and begins the moment an occurrence is materially acquired; generation stamps are rebuildable acceleration metadata; Region is not automatically a Context Scope; and Desired going empty is not automatically permission to release.

Colour in the diagram is meaningful: warm sand marks durable authority, cool cyan marks derived and disposable state, and the travelling pulse changes temperature at the exact moment durable truth becomes runtime projection.
